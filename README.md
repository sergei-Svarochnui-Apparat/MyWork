# AiSensor — первый этап отслеживания

Ветка TestBranch. Зелёный квадрат — фиксированный прицел в центре изображения.
Красная рамка — выбранный человек. Физическое перемещение мыши должно менять
направление внешней камеры/изображения, чтобы прицел оказался немного внутри красной рамки.
Если веб-камера снимает монитор, центр прицела в снимаемом окне может не совпасть
с центром кадра камеры: настрой его щелчком по видео. «Прицел в центр» сбрасывает
положение в центр кадра. Положение сохраняется до закрытия программы.

## Запуск

Открыть Testfowm.slnx в Visual Studio либо выполнить:
```
dotnet run --project Testfowm/Testfowm.csproj
```
Выбрать веб-камеру и нажать «Запустить камеру».
Порог уверенности регулируется в окне (начальное значение 40%).
При снижении порога появляется больше рамок, включая возможные ложные цели.
Показ видео и распознавание работают
независимо: YOLO обрабатывает только свежий доступный кадр, без очереди старых кадров.
Красная рамка показывает выбранного человека, жёлтые — остальных.
Зелёный квадрат прицела — 30×30 px вместо прежних 75×75 px.
Циановая линия связывает центр прицела с ближайшей точкой внутренней зоны цели.
ΔX > 0 означает цель справа; ΔY > 0 — ниже выбранного прицела.
Статус показывает расстояние до внутренней зоны: в ней ошибка равна нулю.
Попадание — центр прицела минимум на 8 px внутри рамки по каждой оси.
Для очень маленькой рамки отступ ограничен четвертью её ширины/высоты.
Автоматика управляет X и Y одновременно.

Первая цель выбирается ближайшей к центру, затем связывается с предыдущей по
пересечению рамок и расстоянию. Это геометрическое сопровождение, а не распознавание
личности: при пересечении людей возможна смена цели. Пропавшие координаты не выдаются
как новая цель; после секунды потери допускается выбор нового человека.
Рамки старше 750 ms скрываются. Этот порог относится к показу, а допустимая задержка
будущего управления рукой должна определяться отдельно при калибровке.

## Что изменено

- Распознавание вынесено из потока окна; показ камеры больше не ждёт каждый запуск YOLO.
- Захват предпочитает 800×600 с наибольшей доступной частотой для этого размера.
  Если 800×600 нет, выбирает поддерживаемый режим от 320×240 до 800×600,
  отдавая предпочтение частоте от 30 FPS, затем большему кадру и частоте.
  Если и этих размеров нет, выбирает наиболее быстрый доступный режим.
- Изображение для YOLO сохраняет пропорции: масштабирование и поля вместо растягивания.
- Дублирующиеся рамки удаляются NMS, используется только класс person.
- Размер выхода проверяется; модель берётся из Models рядом с исполняемым файлом.
- Модель, кадры и фоновые задачи освобождаются при остановке.
- Кадр клонируется для читателя только при новом номере; одинаковые кадры не копируются.
- Буфер Bitmap для подготовки входа YOLO используется повторно.
- Результат распознавания передаётся наведению сразу через поток окна,
  независимо от следующего тика показа видео.
- Прицел вычисляется от реального размера кадра и настраивается щелчком по видео;
  обе координаты ошибки видны в окне.

## Рука и COM-порт

Добавлена собственная прошивка [RobotBridge](Firmware/RobotBridge/README.md) и
нижняя панель управления тремя известными приводами. Протокол AISENSOR 1 одинаков
на ПК и ESP32: отдельные шаги по суставам, плавное движение, ACK/DONE, STOP и watchdog.
Порт выбирается явно и открывается один раз. После подключения приводы активируются
отдельной кнопкой, начальная поза 47° / 110° / 43° взята из старого скетча.
Она не измеряется автоматически; первое включение может переместить руку.

Автослежение X/Y начинается автоматически после запуска камеры и включения приводов.
«СТОП» отключает слежение до явного возобновления.
Ручная калибровка использует шаг 0.1–2°.
Текущие окна: основание 12–82°, плечо 80–140°, локоть 13–73°.
Каждый край прежнего тестового окна расширен на 25° по запросу пользователя.
Это программные ограничения, а не подтверждённые механические пределы.
Новую прошивку нужно загрузить вместо старой f/b/k/h либо одноразового теста основания.
Четвёртый привод SG90 подключается к GPIO26 (D26) и управляется отдельной панелью.
Выбрать угол и скорость, нажать «Включить D26», затем «Задать угол» или D26 − / +.
Первое включение сразу задаёт выбранный угол (начально 90°); последующие переходы
плавные. «Стоп D26» удерживает угол, «Отключить D26» снимает PWM и удержание.
Общий «СТОП» останавливает руку и D26. Камера не включает D26 автоматически.
Для новых кнопок требуется обновлённая прошивка RobotBridge.
Командные углы D26 доступны от 0 до 180°, скорость перехода — 15–180°/с.
Это программная шкала, а не измеренные физические углы и не обороты двигателя.
Подробнее: [управление SG90](Firmware/RobotBridge/README.md#sg90-на-d26).

Для следующего этапа измеряем смещение цели в изображении при известных малых
изменениях углов. Это позволит определить направление и местный коэффициент
управления по обратной связи; старый постоянный k больше не используется.
Сначала также нужно проверить контакт мыши с поверхностью и сочетания углов звеньев.
Подробная последовательность и команды — в README прошивки.

## Авто X/Y по видео через существующие команды

Изменения только в приложении: прошивка, её команды и аппаратные диапазоны прежние.
Программа отправляет обычные MOVE с тремя углами, ждёт DONE, затем использует новое
изображение, полученное строго после движения и настраиваемой паузы (начально 0 ms). Старая очередь кадров не
используется. Одновременно выполняется одна команда движения; STOP может её прервать.

Запустить камеру, настроить прицел щелчком по видео, подключить ESP32 и активировать
приводы. Для первого включения авто нужна исходная поза 47° / 110° / 43° либо поза
на записанном пути Y с основанием в диапазоне 17–77°. Когда готовы камера, связь и
приводы, авто начинает ждать цель и затем наводится без галочек. По X и Y всегда
работают оба регулятора. «СТОП» останавливает и отключает авто; появление новых кадров
или цели не запускает его повторно. «Продолжить наведение» возобновляет ожидание
или слежение. Явный новый запуск камеры, подключение порта или включение приводов
также запрашивает автозапуск. Для ручных замеров сначала нажать «СТОП».
Цель справа от прицела — основание уменьшается к 17° (мышь вправо), цель слева —
увеличивается к 77° (мышь влево). Центр 47°, запас по 30° в обе стороны.
Прицел ниже красной цели — плечо
увеличивается и локоть рассчитывается по записанным парам; прицел выше — обратный ход.
Ошибка управления считается до внутренней зоны красной рамки с отступом 8 px.
При входе в эту зону движение сразу прекращается, независимо от старой ошибки
фильтра. После остановки допускается отход до 4 px от зоны, чтобы не поправляться
на каждое дрожание рамки.
Для маленьких целей отступ ограничен четвертью размера, поэтому зона не исчезает.
Доводка до центра по-прежнему не требуется.
Основание и плечо
получают цели одной командой MOVE; локоть рассчитывается по таблице Y. Достижение
границы одной оси не прекращает коррекции другой. Точное совмещение может быть
недостижимо в пределах участка или при потере контакта мыши.

Галочки режима, выбора оси, обращения направления и сглаживания убраны.
Направления фиксированы по последней калибровке: вправо — уменьшение основания,
влево — увеличение; вверх — увеличение плеча, вниз — уменьшение.
«Макс. шаг X, °» регулируется от 0.1 до 2° основания (начально 2° вместо 0.5°).
«Макс. шаг Y, °» задаёт предел коррекции
плеча 0.1–2° (начально 2°, по наблюдениям пользователя). Вдали от центра используется
больший шаг; при приближении он уменьшается до 0.1°. Полный желаемый шаг достигается,
когда ошибка за пределами
внутренней зоны составляет не менее 4% высоты кадра для Y и ширины кадра для X.
«Пауза, мс» регулируется от 0 до
500 ms: после DONE программа ждёт кадр, снятый после окончания движения и заданной
паузы. Даже при 0 ms изображение до DONE не используется. Цикл управления
проверяет готовность каждые 20 ms. Задержки камеры, распознавания и движения добавляются
к паузе, поэтому она не равна полному времени между коррекциями.
Шаги X/Y и паузу можно менять при включённом авто; следующая коррекция использует новые
значения. Начальные значения X 2° / Y 2° / пауза 0 ms выбраны для более быстрого
наведения по запросу пользователя. При проскакивании цели уменьшить шаг или увеличить паузу.
Угловой шаг не равен миллиметрам мыши или пикселям изображения. Команды и состояния записываются
в существующий журнал. Сохранение ручных контрольных точек доступно после выключения авто.

Для каждой оси вдали от рамки используется текущая ошибка без задержки фильтра,
рядом — отдельный фильтр с постоянной времени 40 ms. Повторный показ одного кадра
не используется как новое измерение. Вдали шаг увеличивается до 1° за коррекцию,
рядом — до 0.35°, уменьшается сразу по мере приближения. Рядом с рамкой разворот
подтверждается двумя разными свежими кадрами и первый обратный шаг ограничен 0.25°;
вдали дополнительное ожидание подтверждения убрано. Если сырая ошибка пересекла рамку, программа
не продолжает движение по старому направлению фильтра. При потере цели или изменении
положения прицела фильтр сбрасывается. Сглаживание рядом с рамкой работает автоматически.
Сглаживание добавляет задержку реакции. Физические остановки между MOVE и независимое
движение суставов внутри MOVE сохраняются: непрерывная траектория с разгоном и
торможением потребует отдельного изменения прошивки и проверки контакта мыши.

После отсутствия свежей цели в течение 700 ms приложение постепенно возвращает
руку по тем же парам углов в 47° / 110° / 43°, шагом не больше 0.5° плеча и заданного
максимума Y. Основание возвращается к 47° шагом не больше 0.5° и заданного максимума X.
При новом обнаружении
возврат уступает место слежению. До первого обнаружения цели авто просто ожидает.
При устаревании кадров не используется прежняя рамка; если камера остаётся без свежей
цели, действует тот же возврат. Остановка камеры, отключение порта и
STOP отключают авто и прерывают движение, без автоматического возврата на выходе.

Рабочий диапазон для авто: основание 17–77°, плечо 110–135°, локоть 43–67°.
Пользователь проверил поворот основания от 47° до 40° вправо и до 57° влево
шагами 0.5°, сообщил о плавном движении без заметного люфта. Ход по 30° от 47°
установлен по его отдельному запросу; участки 17–40°, 57–77° и все сочетания с позами Y
не подтверждены этими замерами. Чувствительность X в пикселях на градус не измерена:
шаг определяется ошибкой изображения, а новая рамка проверяется после движения.
За исходную позу назад режим не идёт: для обратного хода сначала нужен запас впереди.
В расчёте использованы пары двух сеансов записи; точки с пометкой «плохо» исключены.
Промежуточные цели получаются линейной интерполяцией на ПК. При неизвестной позе или
потере свежей связи с ESP32 авто выключается, без скачка на путь или слепого возврата.

Прошивка исполняет MOVE по своим прежним правилам. Приложение согласует целевые углы,
но датчиков контакта и положения нет; точная траектория между целями и разный отклик
сервоприводов не измеряются. Проверить первое движение на реальной руке малым шагом.
Параметры чувствительности изображения ещё не измерены; текущий регулятор использует
небольшие шаги и обратную связь по новой рамке, с ограничением рабочего участка.

## Подстройка шага по изображению

После MOVE и нового кадра программа сопоставляет ошибку центра до/после движения
с отправленным угловым шагом. Для каждой оси нужны три согласованных наблюдения.
Используются движения преимущественно одной оси, шаги от 0.2°, смещения от 2 px,
кадры одной размерности и близкий размер цели. Наблюдения дольше 500 ms пропускаются.
Обратный отклик и большие выбросы не принимаются; при трёх несовпадениях с прежней
оценкой чувствительность собирается заново.

После получения оценки желаемый шаг рассчитывается линейно:
`0.75 × расстояние до зоны остановки / наблюдаемое смещение на градус`, с прежними ограничениями
шага и нарастания. Пока данных мало, работает прежний регулятор по размеру ошибки.
Это местная приблизительная оценка, а не измерение механической геометрии:
движение человека, задержка сенсора и смена цели могут повлиять на результат.
Оценка хранится только в памяти текущего запуска камеры. Остановка наведения
сохраняет её; перезапуск камеры и смена размера кадра сбрасывают.

Меньший кадр сокращает копирование и масштабирование, но вход текущей ONNX-модели
остаётся 640×640: сама нейросеть не стала моделью 320×320. Фактическое время YOLO
и частоту показа можно увидеть в статусе. Скорость прошивки остаётся 15°/с,
каждая команда ждёт DONE и следующего свежего кадра. Физическая траектория мыши
не гарантированно прямая: для этого нужны размеры звеньев, высота контакта и
согласованная траектория суставов.

## Запись движений на коврике

В панели руки появилась кнопка «Запомнить точку». Выбрать название положения,
дождаться остановки, подтвердить «Мышь лежит плоско на коврике» и сохранить.
Записываются все три командных угла, время и комментарий. Можно вводить собственные
названия и отмечать промежуточные положения отдельно для движения вперёд и назад.
Сохранение точки не двигает робота. При движении подтверждение контакта сбрасывается.

При запуске создаётся отдельная папка в `%LOCALAPPDATA%/AiSensor/Calibration`.
«Путь к записи» копирует путь к текущей папке. В ней `live.json` показывает последнее
состояние руки, `live-aux.json` — последнее состояние D26,
`points.jsonl` содержит подтверждённые точки, `trace-*.jsonl` — телеметрию
и команды. Запись файлов идёт в отдельной задаче; камера и COM-порт для наблюдателя
повторно не открываются. Подробнее: [настройка по реальным позам](CALIBRATION.md).

Окна углов расширены на 25° в каждую сторону. Их граница с ошибкой LIMIT не означает
найденный механический предел. Экстремальные точки сами по себе не задают допустимый
путь между ними. Автоматическое воспроизведение и движение назад через подготовительную
позу пока не реализованы: последовательность должна быть записана и проверена.

Сборка не проверяет лаг реальной камеры, механические пределы и движение руки:
это требует подключённого оборудования и измерений.
При сборке остаются предупреждения NU1701 у прежних пакетов AForge 2.2.5:
они рассчитаны на .NET Framework, тогда как проект использует .NET 10.
Фактический захват камеры нужно проверить на выбранном устройстве.
