# AiSensor — первый этап отслеживания

Ветка TestBranch. Зелёный квадрат — фиксированный прицел в центре изображения.
Красная рамка — выбранный человек. Физическое перемещение мыши должно менять
направление внешней камеры/изображения, чтобы прицел оказался внутри красной рамки.
Если веб-камера снимает монитор, центр прицела в снимаемом окне может не совпасть
с центром кадра камеры: настрой его щелчком по видео. «Прицел в центр» сбрасывает
положение в центр кадра. Положение сохраняется до закрытия программы.

## Запуск

Открыть Testfowm.slnx в Visual Studio либо выполнить:
```
dotnet run --project Testfowm/Testfowm.csproj
```
Выбрать веб-камеру и нажать «Запустить камеру».
Порог уверенности регулируется в окне (начальное значение 40%).
При снижении порога появляется больше рамок, включая возможные ложные цели.
Показ видео и распознавание работают
независимо: YOLO обрабатывает только свежий доступный кадр, без очереди старых кадров.
Красная рамка показывает выбранного человека, жёлтые — остальных.
Циановая линия связывает центр прицела и центр цели.
ΔX > 0 означает цель справа; ΔY > 0 — ниже выбранного прицела.
Зелёный квадрат считается совмещённым, когда целиком находится внутри красной рамки.

Первая цель выбирается ближайшей к центру, затем связывается с предыдущей по
пересечению рамок и расстоянию. Это геометрическое сопровождение, а не распознавание
личности: при пересечении людей возможна смена цели. Пропавшие координаты не выдаются
как новая цель; после секунды потери допускается выбор нового человека.
Рамки старше 750 ms скрываются. Этот порог относится к показу, а допустимая задержка
будущего управления рукой должна определяться отдельно при калибровке.

## Что изменено

- Распознавание вынесено из потока окна; показ камеры больше не ждёт каждый запуск YOLO.
- Размер кадра выбирается из поддерживаемых режимов, желательно не выше 1280×720.
- Изображение для YOLO сохраняет пропорции: масштабирование и поля вместо растягивания.
- Дублирующиеся рамки удаляются NMS, используется только класс person.
- Размер выхода проверяется; модель берётся из Models рядом с исполняемым файлом.
- Модель, кадры и фоновые задачи освобождаются при остановке.
- Прицел вычисляется от реального размера кадра и настраивается щелчком по видео;
  обе координаты ошибки видны в окне.

## Рука и COM-порт

Добавлена собственная прошивка [RobotBridge](Firmware/RobotBridge/README.md) и
нижняя панель управления тремя известными приводами. Протокол AISENSOR 1 одинаков
на ПК и ESP32: отдельные шаги по суставам, плавное движение, ACK/DONE, STOP и watchdog.
Порт выбирается явно и открывается один раз. После подключения приводы активируются
отдельной кнопкой, начальная поза 47° / 110° / 43° взята из старого скетча.
Она не измеряется автоматически; первое включение может переместить руку.

Автослежение пока отключено, доступна ручная калибровка с шагом 0.1–2°.
Текущие окна: основание 12–82°, плечо 80–140°, локоть 13–73°.
Каждый край прежнего тестового окна расширен на 25° по запросу пользователя.
Это программные ограничения, а не подтверждённые механические пределы.
Новую прошивку нужно загрузить вместо старой f/b/k/h либо одноразового теста основания.
Четвёртый привод отсутствует в этой версии.

Для следующего этапа измеряем смещение цели в изображении при известных малых
изменениях углов. Это позволит определить направление и местный коэффициент
управления по обратной связи; старый постоянный k больше не используется.
Сначала также нужно проверить контакт мыши с поверхностью и сочетания углов звеньев.
Подробная последовательность и команды — в README прошивки.

## Запись движений на коврике

В панели руки появилась кнопка «Запомнить точку». Выбрать название положения,
дождаться остановки, подтвердить «Мышь лежит плоско на коврике» и сохранить.
Записываются все три командных угла, время и комментарий. Можно вводить собственные
названия и отмечать промежуточные положения отдельно для движения вперёд и назад.
Сохранение точки не двигает робота. При движении подтверждение контакта сбрасывается.

При запуске создаётся отдельная папка в `%LOCALAPPDATA%/AiSensor/Calibration`.
«Путь к записи» копирует путь к текущей папке. В ней `live.json` показывает последнее
состояние, `points.jsonl` содержит подтверждённые точки, `trace-*.jsonl` — телеметрию
и команды. Запись файлов идёт в отдельной задаче; камера и COM-порт для наблюдателя
повторно не открываются. Подробнее: [настройка по реальным позам](CALIBRATION.md).

Окна углов расширены на 25° в каждую сторону. Их граница с ошибкой LIMIT не означает
найденный механический предел. Экстремальные точки сами по себе не задают допустимый
путь между ними. Автоматическое воспроизведение и движение назад через подготовительную
позу пока не реализованы: последовательность должна быть записана и проверена.

Сборка не проверяет лаг реальной камеры, механические пределы и движение руки:
это требует подключённого оборудования и измерений.
При сборке остаются предупреждения NU1701 у прежних пакетов AForge 2.2.5:
они рассчитаны на .NET Framework, тогда как проект использует .NET 10.
Фактический захват камеры нужно проверить на выбранном устройстве.
