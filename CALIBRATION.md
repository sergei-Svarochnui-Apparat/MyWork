# Настройка руки по реальным положениям мыши

Исходная поза уже лежит на коврике. Рука имеет систему связанных тяг; по фотографии
нельзя установить все оси, направления вращения и ограничения. Для первого этапа
записываем проверенные совместные положения трёх приводов и последовательность
переходов между ними. Размеры звеньев для самой записи не требуются.

## Первая запись

1. Перезапустить обновлённое приложение; прошивку RobotBridge менять не требуется.
2. Подключить ESP32. После остановки в исходной позе выбрать «Исходная поза»,
   подтвердить «Мышь лежит плоско на коврике», нажать «Запомнить точку».
3. Двигаться небольшими ручными шагами, начиная с 0.1–0.5°. После каждого изменения
   проверять контакт мыши. Сохранять промежуточные положения с понятными названиями.
4. Для левого/правого направления отметить X; для вперёд/назад — Y. Это направления
   на коврике, не знаки ошибки цели в изображении. Соответствие изображению измерим
   отдельно. Название можно вводить вручную; комментарий описывает действие и результат.
5. Отметить края уже исследованного участка. Не искать механический упор усилием:
   ошибку LIMIT даёт существующее программное окно, а не датчик предела.
6. Для движения назад отдельно записать «Подготовка к движению назад», затем
   промежуточные точки обратного хода. В комментарии указать, какие суставы и в каком
   порядке менялись, и где мышь оставалась на поверхности.

Сохранение разрешено только после остановки, при активных приводах и телеметрии
моложе 750 ms. Контакт подтверждается пользователем, автоматически он не измеряется.
Подтверждение снимается при новой команде или изменении полученных углов.
Кнопка сохранения не отправляет команды в COM-порт и не меняет HOME.

Пользователь сообщил, что для движения назад сначала требуется движение вперёд.
До выяснения причины нельзя считать обратный путь зеркальным к прямому. Существующая
команда HOME задаёт суставные цели независимо и пока не учитывает эту подготовку;
не использовать её как проверенный путь возврата с мышью на коврике. Сохранённые
точки также не разрешают автоматическое движение между ними: промежуточный путь
и поведение под нагрузкой требуют проверки.

## Файлы для совместного наблюдения

Папка каждой записи: `%LOCALAPPDATA%/AiSensor/Calibration/<UTC-время>-<метка>`.
Кнопка «Путь к записи» копирует её полный путь.

- `live.json` — последнее состояние с временем UTC и признаком подключения.
- `points.jsonl` — подтверждённые точки, по одному JSON на строку.
- `trace-001.jsonl`, затем следующие части — состояния и результаты команд;
  новая часть создаётся примерно после 5 MB, старые части сохраняются.

Поля `Base`, `Shoulder`, `Elbow` — командные углы, не измерение реального положения.
`contactConfirmedByUser: true` означает только ручное подтверждение контакта.
`sequence` сохраняет порядок записей; `note` позволяет описать путь входа в позу.
Команда с `command-sent` ещё не означает выполненное движение: нужно учитывать
`command-done` либо `command-failed` и следующую телеметрию.

При потере связи смотрим время последнего состояния, а не старые углы в файле.
Сборщик записывает телеметрию отдельно от COM-потока. Если диск не успевает, часть
обычных записей может пропускаться; интерфейс сообщает об этом. Сохранённая точка
подтверждается только после записи на диск. Ошибка записи также выводится в окне.

Ассистент может считывать эти файлы во время совместной работы. Они не показывают
физический контакт, изображение экрана или механическое столкновение. Для этих
наблюдений нужны описание пользователя, снимок или видео. Отдельные подтверждённые
позы ещё не дают непрерывную функцию компенсации плеча и локтя; после сбора проверим
промежуточные положения и выберем способ движения по записанному пути.
