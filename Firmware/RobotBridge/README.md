# RobotBridge: прошивка ESP32 и проверка руки

Открыть RobotBridge.ino в Arduino IDE, выбрать ESP32 Dev Module, COM-порт платы,
загрузить. Библиотека ESP32Servo уже установлена. Новая прошивка заменяет f/b/k/h:
приложение из этой ветки использует тот же новый протокол AISENSOR 1.

После загрузки приводы НЕ активируются автоматически. При первом ARM они получают
47° / 110° / 43°, поэтому нужно поддержать руку и расположить её близко к этой позе.
Без датчиков прошивка не знает фактических углов: STATE сообщает заданное положение.

| Номер | Назначение | GPIO | Начальный угол | Тестовое окно |
|---|---|---|---|---|
| 0 | Основание | 32 | 47° | 12–82° |
| 1 | Плечо | 33 | 110° | 80–140° |
| 2 | Локоть | 25 | 43° | 13–73° |

Каждый край прежнего тестового окна расширен на 25° по запросу пользователя.
Это НЕ измеренные безопасные пределы.
Первый шаг поставить 0.5° либо 0.1°. Реальные пределы и сочетания углов нужно проверить
на механике: даже допустимые отдельные углы не исключают столкновения звеньев.
Если начальная поза неверна, изменить HOME/currentAngle/targetAngle и соответствующие
MIN_ANGLE/MAX_ANGLE до загрузки. Начальные HOME и массивы должны совпадать.

Включение задаёт начальную позу сразу; плавность от неизвестного физического положения
без обратной связи гарантировать нельзя. После активации движения плавные и дробные,
до 15°/s. Начальный диапазон импульсов 544–2400 µs соответствует прежнему ESP32Servo
write(angle); это не автоматически измеренная калибровка самого сервопривода.

## Проверка из приложения

1. Закрыть монитор порта Arduino IDE, открыть Testfowm.slnx и запустить проект (F5).
2. В нижней панели выбрать COM4 (или актуальный порт) и нажать «Подключить ESP32».
3. При готовой механике нажать «Включить приводы».
4. Проверить основание + / − с шагом 0.5°. Проверить остальные суставы отдельно.
5. «СТОП» отменяет текущую цель движения и удерживает последнее заданное положение.
   Эта команда не отключает питание сервоприводов и не заменяет аппаратное отключение.

При подключении ПК отправляет HELLO с уникальной меткой и проверяет
READY AISENSOR 1 с той же меткой. BOOT AISENSOR 1 сообщает о перезапуске платы;
после перезапуска требуется переподключение. Порт остаётся открытым.
Каждая команда имеет номер, ACK означает принятие, DONE — завершение заданного
перемещения по программным углам. Это не датчик фактического достижения позы.
Автослежение пока отключено: сначала нужно измерить движение мыши и допустимые позы.

При отсутствии PING дольше 1.5 s дальнейшее движение блокируется; PWM и удержание
сохраняются. Для возобновления нужен новый ARM. После обычного STOP при сохранённой
связи можно сразу отправлять следующий шаг. Повторный ARM при уже подключённых
приводах оставляет последнее командное положение, без возврата домой.

## Протокол

Скорость 115200, ASCII, каждая строка заканчивается LF:
- HELLO → останавливает движение, блокирует новые движения до ARM,
  возвращает READY AISENSOR 1 и STATE.
- HELLO <метка> → тот же ответ с добавленной меткой; используется приложением,
  чтобы отличить подтверждение нового подключения от старых данных в порту.
- PING → подтверждение связи без ответа.
- 1 ARM → включить приводы.
- 2 STEP 0 0.5 → относительный шаг основания на +0.5°, максимум 2° за STEP.
- 3 MOVE 47 110 43 → абсолютные цели трёх суставов.
- 4 HOME → плавно вернуться к исходной позе.
- 5 STOP → остановить текущий ход и удерживать положение.
- 6 STATUS → запросить состояние.

Ответы: ACK <id>, DONE <id>, ERR <id> <код>.
Выход за окно отклоняется с LIMIT, вместо скрытого обрезания угла.
Вторая команда движения при незавершённой первой отклоняется с BUSY.
STOP/ARM могут отменить прежнее движение: для него придёт ERR <id> CANCELLED.
Частичные и слишком длинные строки не блокируют основной цикл.

STATE <armed> <moving> <base> <shoulder> <elbow>
      <baseMin> <baseMax> <shoulderMin> <shoulderMax> <elbowMin> <elbowMax>
(фактически это одна строка). Дополнительный NOTICE WATCHDOG сообщает о потере связи.

## Калибровка следующего этапа

Нужно наблюдать изменение изображения при небольшом известном изменении угла.
Для каждого допустимого движения измеряем отклик, например
Jx = (ошибка X после движения − ошибка X до движения) / изменение угла,
аналогично Jy. Для одного измеренного направления локальная поправка
Δугол = −λ * ошибка / J, где λ ограничивает агрессивность движения.
Знак J определится по изображению, а не по названию «влево».

Для движения мыши в двух направлениях нужны независимые измеренные движения.
Компенсация локтя должна также сохранять контакт мыши с поверхностью; один только
коэффициент изображения этого не гарантирует. Для расчёта геометрии потребуются
длины звеньев, точки крепления и направления сервоприводов.

Без живых измерений коэффициенты не подобраны. Сначала нужны ответы:
куда смещается цель при основании +0.5°, какие суставы двигают мышь вперёд/назад
и отрывается ли она от поверхности. Затем можно включать замкнутое регулирование
с ограничениями, небольшими шагами и остановкой при потере цели.

## Проверки

Host-проверка выполняет сам RobotBridge.ino с подменёнными millis/Serial/Servo:
запуск без PWM, ARM, дробные шаги, границы, неправильные числа, BUSY, STOP,
watchdog, длинные и недописанные строки. Реальные двигатели она не включает.

Из корня репозитория:
```
g++ -std=c++17 -I Tests/RobotBridge Tests/RobotBridge/test.cpp -o robot-tests.exe
./robot-tests.exe
```
Дополнительно прошивка компилируется Arduino CLI для esp32:esp32:esp32.
Проверки программы не измеряют механические пределы и фактическое движение.
